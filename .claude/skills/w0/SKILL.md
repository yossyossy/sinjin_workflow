# W0｜受領と復元（10分）

作業指示を受けた直後に行う。**育成のための工程ではない。** 認識ズレと車輪の再発明を着手前に潰すための、案件処理そのものの手順。

## このスキルでAIが行ってよいこと（狭い）

1. 作業中の案件の `W0_受領と復元.md` と `指示文.md` を開く。無ければ先に `/wf-new` を促す。
2. `指示文.md` を読み、**読み取れる要件・制約だけを列挙**する。書かれていない項目は必ず「不明」として挙げる。
   - 使うプロンプトの型：「読み取れる要件と制約を列挙して。書かれていない項目は『不明』として挙げて」
   - **一般論で埋めない。** 「一般的にはこうでしょう」は要件ではなく推測。埋めた瞬間にAI利用の線引き（× 書かれていない要件の補完）に触れる。
3. 列挙した内容と「不明」リストをユーザーに提示する。**「不明」がそのまま質問候補になる。**
4. ユーザーが実際に確認・入手した回答をもとに、`W0_受領と復元.md` の各項目をユーザーと一緒に埋める。**AIが代わりに断定して埋めない。** ユーザー自身の理解として書く。
5. 資料の所在が判明したら、口頭要約ではなく**現物を受領して読む**ようユーザーに促す。読んだ後は「この構成が答えになるような制約は何だったか（推定）」を書かせる（要約ではなく逆算）。
6. 復唱文の下書きを提案してよい（例：「〜という状態になればよく、〜は変更しない、期限は〜、という理解で合っていますか」）。実際に相手に確認するのはユーザー。
7. 記入後、`python scripts/wf_lint.py W0` を実行し、結果をユーザーに見せる。

## やってはいけないこと

- 書かれていない要件をAIが推測で埋める
- 指示文を読まずに「どう作ればいいですか」と手段を先に聞く（手段はW0では聞かない。読んだ上でなお残ったものだけW4に回す）
- 資料の内容をAIが要約してユーザーに渡す（口頭要約と同じ事故。ユーザー自身に読ませる）
